# OpenTunes working rules

Personal hobby project. A Chrome-only web app that puts music, video and podcasts on a classic iPod, with no backend. Read [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) and [docs/ROADMAP.md](docs/ROADMAP.md) before changing anything.

## Rules

1. **Nothing goes on the internet.** No `git push`, deploy, GitHub Pages, hosting or `npm publish` unless the owner asks for it in that message. Packages stay `"private": true`.
2. **Branch per piece of work.** Branch from `main`, merge back locally with `git merge --no-ff`. The old app lives on the `v1-legacy` tag, see [docs/LEGACY.md](docs/LEGACY.md).
3. **Say what was tested.** Every iPod model carries a status in `core/src/devices/registry.ts`: `hardware-tested`, `spec-sourced` or `unverified`. Only the owner's hardware runs can set `hardware-tested`. Never write "works" in docs for anything that has not been run.
4. **Tests import real code.** The old repo tested copies of its logic against mock data. Do not repeat that.
5. **Read before porting.** When reusing old behaviour, read it from the tag (`git show v1-legacy:path/to/file`) and port the logic, not the patch.
6. **Docs stay in step.** Update the phase status in `docs/ROADMAP.md` when an item changes. `docs/DEVICE-SUPPORT.md` is generated by `npm run docs:devices`, so edit the registry, not the file.

## Commands

```
npm install          # once
npm run dev          # app on http://localhost:5173
npm run dev:lan      # same, reachable from a phone on your Wi-Fi (local network only)
npm run check        # typecheck + tests + build
npm run docs:check   # fails if DEVICE-SUPPORT.md is stale
npm run engine:build # engine in Docker (Docker must be running), output in engine/build/
npm run engine:test  # engine tests in Node, need the build above
```
